# Agile / Scrum Plan

## Product goal
Deliver a simple, usable task-management prototype that helps a user track tasks and progress.

## Suggested Scrum roles
- Product Owner: prioritizes requirements.
- Scrum Master: supports the process and removes blockers.
- Developer: builds the interface and functionality.
- Tester: checks requirements and reports defects.

For a solo mini project, one person may perform multiple roles.

## Product backlog
| ID | User story | Priority | Acceptance criteria |
|---|---|---|---|
| US-01 | As a user, I want to add tasks so I can record work. | High | Task appears after a valid title is submitted. |
| US-02 | As a user, I want to edit tasks so I can correct details. | High | Changes are saved to the selected task. |
| US-03 | As a user, I want to change status so I can track progress. | High | Status moves to the next available stage. |
| US-04 | As a user, I want to delete tasks so I can remove obsolete work. | Medium | Confirmation is shown before deletion. |
| US-05 | As a user, I want to search and filter tasks. | Medium | Results match the query and selected status. |
| US-06 | As a user, I want a summary of tasks by status. | Medium | Counts update after each change. |

## Example sprint plan
### Sprint 1 — Core task management
- Build HTML structure and responsive styling.
- Implement add, edit, and delete.
- Validate task title.
- Test the main task workflow.

### Sprint 2 — Tracking and usability
- Add status changes and summary counts.
- Add search and status filtering.
- Save tasks in localStorage.
- Perform acceptance testing and fix issues.

## Definition of Done
- Feature meets its acceptance criteria.
- No known critical issue remains in the tested workflow.
- Code and documentation are committed to GitHub.
- Manual test results are recorded.
